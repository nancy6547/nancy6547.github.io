Zeitaku

TypeScript · testing

A CLI that finds waitForTimeout sleeps in Playwright tests and replaces them with a wait that checks when the network is actually done (using the Chrome DevTools Protocol). I parse the test files with the TypeScript compiler so it doesn't touch comments or strings.

Junban

TypeScript · testing

Finds the exact order of API responses that makes a flaky Playwright test fail. It holds each response in the browser and lets them through in different orders, then shrinks the failure down to one rule like "fails when /api/cart arrives before /api/user" and writes a test that fails every time.

~/kensa

Kensa

Python · RAG testing

Tests a RAG app without knowing the right answers. It changes the input in ways where we know what should happen: reword the question, add an unrelated document, delete the document with the answer, change a number in it. Then it checks the answer reacts correctly and shrinks each failure to the documents that cause it.

DocMind

Python · RAG

Upload a PDF and ask questions about it, scanned PDFs too. It only runs OCR on pages that have no text, which made normal PDFs way faster. If nothing in the doc matches, it just says it doesn't know instead of asking the LLM.

Something I didn't expect

I assumed every waitForTimeout should go. Then I read through real test suites (Documenso, Supabase, n8n and a few more) and about 1 in 6 were there on purpose. They wait before checking that something didn't happen, so removing them would make the test pass when it shouldn't.

So now Zeitaku looks at the next few lines after each sleep before changing it. Out of 240 sleeps it found, 196 were safe to replace and 44 it leaves alone.

zsh — zeitaku
// documenso: we must NOT navigate away
await page.waitForTimeout(1000);
await expect(page).not
  .toHaveURL(/\/admin\/users\/\d+$/);

$ zeitaku scan ./tests
Total waitForTimeout:   240
  replaceable:          196
  intentional:          44  (left alone)
